# 급식 캐시 동시성 처리

## 문제

같은 날짜의 캐시가 없을 때 여러 요청이 동시에 캐시 미스를 확인하면 NEIS를 중복 호출할 수 있다.
기존 `조회 → 없으면 저장` 방식은 별도 요청이 동시에 같은 날짜를 저장할 때 기본키 충돌 가능성도 있었다.

## 구현

- `MealsService`의 Map에 교육청 코드·학교 코드·날짜별 진행 중인 Promise를 보관한다.
- 같은 키의 요청은 외부 조회, 응답 정규화, DB 저장까지 동일한 작업 결과를 기다린다(single-flight).
- 강제 갱신 요청도 진행 중인 작업을 공유한다. 갱신 중 들어온 일반 요청은 오래된 캐시 대신 새 결과를 기다린다.
- 캐시 조회가 늦게 끝난 경우 저장된 최신 캐시를 재확인해 불필요한 추가 조회를 막는다.
- 작업 완료 또는 실패 시 `finally`에서 Map 항목을 제거해 다음 요청의 갱신·재시도를 허용한다.
- NEIS 요청에 10초 제한을 적용하고 HTTP 오류·네트워크 오류·JSON 파싱 실패를 실패 응답으로 처리한다.
- TypeORM `upsert`로 PostgreSQL의 `ON CONFLICT (meal_date) DO UPDATE`를 사용한다. 캐시 저장은 조회 후 분기하지 않고 하나의 SQL 작업으로 처리한다.

```text
동일 날짜 요청 20개
       ↓
유효 캐시 또는 진행 중인 작업 확인
       ├─ 캐시 있음 → 캐시 반환
       ├─ 작업 있음 → 기존 Promise 기다림
       └─ 둘 다 없음 → NEIS 조회 → 정규화 → DB upsert
                                            ↓
                                기다리던 요청에 같은 결과 반환
```

## 적용 범위와 한계

- 요청 공유는 하나의 NestJS `MealsService` 인스턴스, 즉 현재 단일 API 프로세스 안에서 유효하다.
- 여러 API 프로세스/서버 사이에서는 NEIS 호출을 합치지 않는다. 분산 요청 공유가 필요하면 Redis 등 별도 조정 수단이 필요하다.
- DB upsert는 여러 인스턴스의 동시 저장에서도 기본키 충돌을 방지한다. 갱신 순서나 최신 응답 우선 적용까지 보장하는 기능은 아니다.
- 기존 단일 학교 설정과 날짜 기본키를 유지한다. 다중 학교 서비스를 지원하려면 DB 키에도 학교 식별자를 포함해야 한다.
- 기존 빈 급식 결과(`{}`)는 저장하되 다음 조회에서 재사용하지 않는 정책을 유지한다.

## 검증

2026-10-04 로컬 검증: Node.js 24.8.0, PostgreSQL 18.3. 운영 서버 및 운영 DB는 변경하지 않았다.
실제 NEIS API는 호출하지 않고 지연을 제어할 수 있는 가짜 응답을 사용했다.
통합 테스트를 포함한 21개 테스트와 TypeScript 빌드를 모두 통과했다.

| 시나리오 | 요청 수 | NEIS 모의 호출 | 캐시 행 | 오류 |
| --- | ---: | ---: | ---: | ---: |
| 유효 캐시 재사용(메모리 저장소) | 20 | 0 | 1 | 0 |
| 동일 날짜 캐시 미스, 단일 서비스(실제 PostgreSQL) | 20 | 1 | 1 | 0 |
| 독립 서비스 20개의 동시 upsert(실제 PostgreSQL) | 20 | 20 | 1 | 0 |

강제 갱신 공유, 갱신 중 일반 조회, 서로 다른 날짜, 저장 완료 전 요청 공유,
네트워크/HTTP/파싱/DB 실패 후 재시도, 지연된 캐시 조회도 테스트한다.
이 결과는 서비스 메서드 동시성 검증이며 운영 HTTP 부하 테스트나 응답속도 개선 측정은 아니다.

단위 테스트:

```sh
npm run test:meals
```

PostgreSQL 통합 테스트는 운영 DB가 아닌 별도의 로컬 테스트 DB를 만든 뒤 실행한다.
호스트는 localhost/127.0.0.1/::1만, DB 이름은 `classpage_meals_test` 또는 `classpage_meals_test_` 접두사만 허용한다.
테스트 중 해당 DB의 `meal_cache` 테이블을 비우므로 반드시 폐기 가능한 DB를 사용한다.

```sh
MEALS_TEST_DATABASE_URL='postgresql://USER@127.0.0.1:PORT/classpage_meals_test' npm run test:meals
```

환경 변수가 없으면 통합 테스트만 건너뛴다. 신규 의존성 및 DB 스키마 변경은 없다.
